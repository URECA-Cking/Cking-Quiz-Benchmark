# Pilot 평가 기준

모든 방식은 같은 영상, 질문 3개, 보기 4개, 프롬프트 버전, 반복 횟수로 비교합니다. 접근 실패·요청 제한·파싱 실패도 결과에서 누락하지 않습니다.

| 항목 | 자동 기록 | 사람 검수 |
| --- | --- | --- |
| API/파싱 성공 | 상태, 오류 범주, 필수 필드 및 타입 | 필요 시 오류 분류 확인 |
| BE 호환성 | A/C에서 `sourceEvidence ∈ contentText` 및 Core 계약 검사; B는 `not_applicable` | 근거의 의미 확인 |
| 관련성·정답 정확성 | 자동 판정하지 않음 | 원본 영상 또는 허가된 원문과 대조 |
| 근거성·환각 | 문자열 포함 여부만 자동 판정 | 근거가 실제 영상에 있고 정답을 뒷받침하는지 확인 |
| 중복·모호성 | 동일 문구 후보 탐지 | 보기의 중의성 및 여러 정답 가능성 확인 |
| 안정성 | 같은 조건 반복 결과와 실패율 | 품질 변동 확인 |
| 지연·사용량·비용 | latency, input/output/thinking tokens, 제공된 usage, 공식 가격 기준 추정 | 가격 적용 조건 검토 |

사람 검수는 질문별로 `pass`, `fail`, `uncertain`을 기록하고 판단 근거를 남깁니다. `uncertain`을 성공으로 합산하지 않습니다. Timestamp나 모델이 작성한 `sourceEvidence` 문장만으로 영상 사실성이 입증되지 않습니다. C에서 transcript 사용 권한이 없거나 자막이 없으면 해당 조건을 실패 또는 실행 불가로 기록하고 다른 방식의 성공으로 대체하지 않습니다.
